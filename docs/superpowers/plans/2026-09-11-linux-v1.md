# Shared Linux V1 implementation plan

Execution follows Renny's approved namespace design and execution brakes.
One implementation, verification, review, at most one remediation and scoped
re-review. Android startup is already closed; no forced service-kill tests.

## Architecture and boundaries

One root-owned named network namespace contains the independent pinned NetBird
peer and managed browser. `pasta` supplies only outbound underlay connectivity,
bound to the host's ordinary default interface, with all inbound and namespace
port forwarding disabled. No host routes, bridges, NAT or DNS changes. Namespace
firewall restricts non-root browser traffic to the IWS interface and production
endpoint TCP 443 and DNS TCP/UDP 53. The root transport has ordinary control-plane
access. Browser runs unprivileged with a dedicated profile, no certificate bypass,
and namespace-specific resolver configuration. Namespace entry is through a fixed
root-owned launcher, never a general command-execution interface.

Host default networking is not a path to the private interface. OLECLANKY's
existing service, peer, state and routes are never reused or changed. Native
system CA trust receives only the existing public IWS root certificate.

## Ordered work

1. Test-first shared namespace controller and fail-closed launcher configuration
   under `linux/`, behavioral tests under `linux/tests/`. Verify namespace/TUN and
   outbound uplink compatibility on real Ubuntu before packaging. Record host
   before-state; namespaces/firewalls remain separate from existing host state.
2. Extend canonical `packaging/package-device.mjs` with one Linux packager,
   native `.deb`/`.rpm` wrappers around identical files. Protected bootstrap input,
   expiry validation, own state, cleanup and metadata follow existing semantics.
3. In a separate Stack worktree extend the existing platform union/enum/UI and
   package dispatch for `LINUX_DEBIAN` and `LINUX_FEDORA`, with lifecycle unchanged.
   Test existing APIs and generation metadata; no second provisioning workflow.
4. Generate and physically install each artifact. Prove one-use enrollment,
   HTTPS Portal/API/WSS, browser child-process boundary, no host route/DNS leak,
   ordinary host networking, OLE staging preservation, reboot and ordinary
   loss/recovery, revoke/access loss, explicit re-provision/new identity.
5. Run relevant Windows/Android automated regression suites once after Linux
   changes. One bounded review/remediation allowance; no new acceptance scenarios.
6. Only after the full two-host matrix passes: publish normal PRs, freeze V1
   with exact commits/artifact/evidence records, then inspect existing V2 roadmap
   and prepare its first bounded feature task. Do not claim an incomplete gate
   passed. If namespace/NetBird incompatibility is evidenced, stop rather than
   trying another networking architecture.
